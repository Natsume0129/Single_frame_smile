# 视频表情粗切分标注任务 Prompt

你需要对给定视频进行基础表情状态切分。  
本任务是实验性的粗标注，不需要输出 timestamp，也不要输出 JSON。  
所有时间边界都必须使用 **帧号 frame index** 表示。

请根据视频画面，将视频按时间顺序切分为以下三类状态：

1. `smile`
2. `neutral`
3. `occlusion`

---

## 一、标签定义

### 1. smile

当被试脸上出现明显或较明显的笑容时，标注为 `smile`。

包括：

- 嘴角上扬
- 露齿笑
- 闭嘴微笑
- 笑容正在形成
- 笑容正在保持
- 笑容正在消退，但仍然能看出笑意
- 苦笑、礼貌笑、真实笑、模糊笑等所有笑容状态

注意：

- 本阶段不需要区分笑容类型。
- 只要能判断为“正在笑”或“仍有笑意”，都标注为 `smile`。
- 如果笑容很轻微，但嘴角、脸颊或眼部有明显笑容迹象，也标注为 `smile`。

---

### 2. neutral

当被试脸部处于自然、非笑状态时，标注为 `neutral`。

包括：

- 自然表情
- 无明显笑意
- 认真听别人说话
- 普通说话状态
- 嘴部有说话动作，但不是笑
- 表情变化较小，无法判断为笑

注意：

- 说话时嘴巴运动，不等于笑。
- 只有当嘴角上扬、脸颊抬起、眼部或整体表情明显带有笑意时，才标注为 `smile`。
- 如果无法确定是否在笑，优先标注为 `neutral`，并在 note 中写 `uncertain_smile`。

---

### 3. occlusion

当脸部被遮挡，导致无法可靠判断表情时，标注为 `occlusion`。

包括：

- 手遮住嘴部、脸颊、眼睛或大部分面部
- 水杯、纸张、麦克风、头发等遮挡关键面部区域
- 脸转得太偏，无法判断表情
- 低头、出画、脸部检测困难
- 画面模糊、运动过快，无法判断表情
- 其他人或物体挡住被试面部

注意：

- 如果遮挡很轻微，不影响判断，可以不标注为 `occlusion`。
- 如果嘴部被部分遮挡，但仍能明确判断为笑，可以标注为 `smile`，并在 note 中写 `partial_occlusion`。
- 如果遮挡影响了判断，优先标注为 `occlusion`。

---

## 二、切分原则

请按照视频帧号顺序，将视频切分成连续片段。

每个片段必须包含：

- `start_frame`
- `end_frame`
- `label`
- `confidence`
- `note`

其中：

- `start_frame` 表示该片段开始帧号
- `end_frame` 表示该片段结束帧号
- `label` 只能是 `smile`、`neutral`、`occlusion`
- `confidence` 使用 0 到 1 之间的小数
- `note` 简短说明判断依据

---

## 三、输出格式

请只输出 CSV 文本，不要输出 Markdown 表格，不要输出 JSON，不要输出额外解释。

格式如下：

```csv
start_frame,end_frame,label,confidence,note
0,102,neutral,0.86,自然表情，没有明显笑意
103,238,smile,0.91,嘴角上扬，脸颊抬起，出现明显笑容
239,276,occlusion,0.88,手遮挡嘴部和下半张脸，无法可靠判断表情
```

---

## 四、帧边界规则

### smile 的开始帧

当出现以下现象之一时，可以认为 `smile` 开始：

- 嘴角开始上扬
- 脸颊开始抬起
- 眼部出现笑意
- 表情从自然状态明显转向笑容

### smile 的结束帧

当以下现象出现时，可以认为 `smile` 结束：

- 嘴角回落
- 脸颊放松
- 表情恢复自然
- 笑意基本消失

注意：

- 笑容消退阶段如果仍能看出笑意，仍然算作 `smile`。
- 不要过早结束 `smile` 片段。
- 如果 `smile` 和 `neutral` 之间变化很平滑，请选择最合理的中间帧作为边界。

### occlusion 的开始帧

当遮挡开始影响表情判断时，标注为 `occlusion`。

### occlusion 的结束帧

当遮挡解除，脸部重新可以可靠判断表情时，结束 `occlusion`。

---

## 五、最小片段长度

为了避免过度切分，请遵守以下规则：

- 少于 15 帧的短暂变化，一般不要单独切分。
- 如果短暂遮挡不影响判断，可以合并到前后片段中。
- 如果短暂遮挡严重影响判断，即使时间较短，也可以标注为 `occlusion`。
- 如果一个状态持续超过 15 帧，应尽量单独切分。

如果视频不是 30fps，请按照以下原则理解：

- 约 0.5 秒以内的短暂变化，一般不单独切分。
- 明显影响判断的遮挡除外。

---

## 六、优先级规则

当多个标签可能同时成立时，请按照以下优先级判断：

```text
严重遮挡，无法判断表情 → occlusion
可以判断为笑 → smile
没有明显笑意 → neutral
```

具体规则：

1. 如果脸部被严重遮挡，无法判断是否在笑，标注为 `occlusion`。
2. 如果有轻微遮挡，但仍能明确判断在笑，标注为 `smile`。
3. 如果没有遮挡，但笑意不明显，标注为 `neutral`。
4. 如果不确定是否为笑，优先标注为 `neutral`，并在 note 中写 `uncertain_smile`。

---

## 七、输出约束

最终输出必须满足：

- 只输出 CSV 文本
- 第一行必须是表头
- 不要输出 Markdown 表格
- 不要输出 JSON
- 不要输出 timestamp
- 不要输出额外解释
- 所有边界都必须使用帧号
- 所有片段必须按帧号顺序排列
- 片段之间不能重叠
- 片段之间尽量不要有空缺
- `start_frame` 和 `end_frame` 必须是整数
- `label` 只能是 `smile`、`neutral`、`occlusion`
- `confidence` 必须是 0 到 1 之间的小数
- `note` 使用简短中文
- 不要细分 smile 类型
- 不要添加额外标签
- 不要输出视频范围之外的帧号

---

## 八、重要提醒

本次输出只是用于后续人工修正的粗切分结果。  
请优先保证大类状态正确，不要为了追求过细边界而频繁切分。

后续人工精标阶段会在 `smile` 片段内部进一步标注：

- true smile
- polite smile
- bitter smile
- smiling but ambiguous
- peak frame

因此，本阶段所有笑容统一标注为 `smile`。
